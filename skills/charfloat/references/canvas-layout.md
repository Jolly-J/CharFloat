# 用矢量形状搭画布页（看板 / 信息图 / 封面页）

在**表格或演示**里用形状拼出一整页版面时，先读这篇。这里的每一条都是真机被打回后总结的，
不是理论——省掉它们就会做出"能看但很业余"的页面。

## 一、开工前先算版面，不要边画边想

**1. 先定纵向节奏，再放元素。**给每个容器写出"上内边距 / 元素间距 / 下内边距"，
再反推容器高度。典型的一行三要素卡片（标签 / 数值 / 环比）：

```
上边距 18 + 标签 16 + 间距 8 + 数值 34 + 间距 6 + 环比 16 + 下边距 14 = 卡片高 112
```

**只按"元素高度之和"给容器高度，底部必然贴边**（真机踩到：KPI 卡片的环比文字压在卡片下边框上）。

**2. 数值必须归一化成高度。**把数据值直接当柱高，最高的柱子一定冲出容器。
先取 `max`，再 `h = 可用高度 × v / max`（真机踩到：152 的柱子冲出面板、数值标签压住面板标题）。

**3. 容器内容不许触底。**按参考稿和内容确定底部留白，写进自检。下表 8pt/0.6pt 是画布示例值，不能覆盖用户现稿要求。

## 二、对齐比的是"视觉中心"，不是"外框"

**框 ≠ 内容。**文本框有内边距（WPS 默认左右各 7.2pt、上 3.6pt），
所以"色块 top 对文本框 top"会让色块**高出文字约 4pt**。

正确做法：

```
Excel 文本框：TextFrame.VerticalAlignment = -4108
PPT 文本框：TextFrame.VerticalAnchor = 3
PPT 水平对齐：TextFrame.TextRange.ParagraphFormat.Alignment = 2
色块 top = 文字中心 - 色块高 / 2
```

同一条原则适用于：图例色块、条形图的侧标签、进度条两侧的文字、任何"图形 + 文字"并排的地方。

## 三、宿主不保证按你请求的尺寸创建对象

**写完必须读回真实宽高再定位。**真机实测：请求宽 80 得到 79.3，请求高 17 得到 20.7。
所以"按请求尺寸算出的对称位置"会偏 1~3pt。

居中标签的可靠做法（三道都要）：

1. `marginLeft = marginRight = 0`——否则默认内边距会把居中文字挤偏；
2. 写完 `list_shapes` 读回真实宽度，再 `update_shape` 设 `left = 中心 - 实际宽 / 2`；
3. 需要贴某个底边时，用**底边反推 top**（`top = 底边 - 实际高`），不要正着算。

## 四、几个会静默失败的地方

| 现象 | 原因 | 做法 |
|---|---|---|
| 白底上文字完全看不见 | 宿主给自选图形**默认白字** | 显式给 `fontColor`；`add_shape` 已按底色亮度自动选黑/白 |
| 框居中了、框里的字还是居左 | 用错 API：`TextFrame.TextRange.ParagraphFormat` **在 Excel 形状上不存在**（那是 PPT 的属性），且错误被 try/catch 吞掉 | Excel 用 `TextFrame.HorizontalAlignment`（-4131 左 / -4108 中 / -4152 右）、`VerticalAlignment`（-4160 上 / -4108 中 / -4107 下） |
| 每段文字都套一个框 | 文本框默认边框/底色没关 | `Line.Visible = 0`、`Fill.Visible = 0`；`add_shape` 已默认关掉，显式给色才画 |
| 截图只有一小块 | 只抓了 `UsedRange`，而 **UsedRange 不含形状** | 截图默认范围已并入所有形状外框；也可显式传 `address` |

**教训**：`try/catch` 包住属性写入又不报错，等于把"没生效"伪装成"成功"。
现在宿主把这类失败写进 `warnings`，**读回体里必须能看到对齐值**（`textAlign` / `textVAlign`）。

## 五、层级与遍历

- **分组会把组插到最前**，组内的形状会盖住之前创建的文字。要么别分组，要么分组后**把文字重新提到最前**。
- **提层时必须先快照名字再逐个移动**：

  ```js
  const names = [];                       // 先快照
  for (let i = 1; i <= ws.Shapes.Count; i++) names.push(String(ws.Shapes.Item(i).Name));
  for (const n of names) ws.Shapes.Item(n).ZOrder(0);   // 再移动
  ```

  直接 `for (i = 1; i <= Count; i++) Shapes.Item(i).ZOrder(0)` 会因为**索引随移动漂移**而漏掉一部分形状
  （真机踩到：KPI 标签被分组盖住，只有最后一张卡片的标签正常）。

## 六、先确认画布与保留边界

```jsonc
// 1. 隐藏网格线，否则所有形状浮在格线上
{ "name": "wps_set_sheet_view", "arguments": { "workbookName": "…", "showGridlines": false } }
```

新建空白演示页时，根据用户设计要求设置背景，并检查占位符和装饰是否与新内容冲突。修改现有页时先学习当前背景、母版和装饰；未经授权不改白底、不删除模板元素。深色背景与文字对比不足时先调整目标文字或局部区域。PPT 修改遵循 [现稿样式协议](../../charfloat-ppt-design/style-protocol.md)。

## 七、字体

形状文字默认走**微软雅黑**（宿主 `DEFAULT_SHAPE_FONT`，可用 `fontName` 覆盖）。
新建中文报表可按任务选择字体；修改既有页优先保留当前稿的字体层级、中文/西文搭配及品牌要求。需要统一时按角色统一并读回，不强制一页只用一种字体。

## 八、交付前自检（不可跳过）

画完先跑一遍核对再交给人看。粗粒度地"看一眼图"会漏掉间距和居中问题。

| 检查 | 判据 |
|---|---|
| 越界 | 所有形状 `left ≥ 0`、`left+width ≤ 画布宽`、`top+height ≤ 画布高` |
| 区块重叠 | 相邻区块的纵向区间不相交 |
| 空文字 | 所有应带文字的形状 `text` 非空 |
| 容器安全距离 | 卡片/面板内的元素**底边**距容器下沿 ≥ 8pt |
| 柱顶间距 | 数值标签底边距柱顶 ≥ 8pt |
| 视觉中心 | 图形中心 vs 旁边文本框中心，容差 ≤ 0.6pt |
| 居中真的生效 | Excel 读回 `textAlign`；PPT 读回 ParagraphFormat.Alignment/VerticalAnchor，不能只看框的位置 |
| 白底白字 | 底色为白且未显式给字色的形状要人工确认 |

**这张表要跟着新发现的问题一起长**——每次被指出问题，就把对应判据补进来。
