# Office Agent Bridge

## 建立并复用任务上下文

首次接入或上下文缺失时调用 `bridge_get_capabilities`，确认宿主、服务版本、连接与验证状态。工具定义已在当前会话可见时直接使用，不再重复拉取整份工具清单；仅缺少定义时查询相关工具。连接异常才调用 `bridge_diagnose`。

读取工作区定位精确 workbookName/documentName/presentationName，以及 sheetName 或目标页。在后续调用显式携带目标，不依赖活动窗口焦点。保留本任务已取得的宿主、目标名称、页面尺寸和对象标识，不在每个子步骤或切换子 skill 时重复初始化。

断线、宿主重启、目标切换或对象不存在时重新确认相关上下文。插入/删除段落、页面、行列后刷新受影响的索引；用户同时编辑时重新读取即将覆盖的内容。缓存用于减少探测，不是跳过修改前的必要核对。

## 按任务组织调用

1. **定位并取够信息。**先摘要或搜索，再读目标区域和所需字段。已有足够数据就开始执行，不为“完整性”读取整份文件。
2. **选择执行粒度。**单项修改用专用工具；连续单元格用范围写入；同一页或同组对象的相关修改可合成一次脚本。批次按失败后可核对、可继续的边界划分，不规定固定调用数。
3. **执行并带回证据。**专用工具已有实际读回信息时直接复用；只有成功标志或缺少关键字段才补读。脚本在写入后读取实际属性并返回普通 JSON 摘要，不只回显输入参数。
4. **针对结果验证。**值和公式检查关键范围；视觉变化在一页或区域完成后预览，不逐对象截图。批量统一版式先验证代表页再扩展，最终检查所有修改页。未改动区域无需重复验证。
5. **按需保存。**用户要求落盘或任务交付需要保存时调用对应保存接口并核对结果。最终简述修改、验证、保存状态和确有的遗留项。

优先使用可批量处理且满足需求的结构化工具。`excel_*` 需按 schema 显式选择 host，`wps_*` 只控制 WPS；Microsoft 通道依实际能力返回和工具定义选择，不照搬 WPS 对象模型。

专用工具未覆盖不等于不支持。需要矢量绘图、已有对象深度编辑或精细布局时，按 [原生脚本](references/native-scripting.md) 只读探测相关 API，再批量执行；不因使用 JS 本身重复索要授权。已有已验证的 API 可复用，不必逐次反射。

## 批次与恢复

同一宿主中的修改、激活与截图串行执行，避免争用焦点或剪贴板。脚本批次开始前检查目标、数据尺寸和必需参数；执行中记录已完成对象及当前步骤。遇到失败停止依赖该步骤的后续修改，返回部分结果，不吞掉错误继续报全量成功。

超时、断线或审计失败可能已经修改文件，先读回目标，不盲目重放整批。仅 `patch_cells` 的值与公式有审计回滚；不要为减少调用把要求审计的单元格写入改成任意脚本。格式、图表、Word/PPT 和脚本没有统一回滚。

没有连接时修复连接，不以离线修改另一份文件替代实时任务。用户明确选择离线时遵循其选择。
