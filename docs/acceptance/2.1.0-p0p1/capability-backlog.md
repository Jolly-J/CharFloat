# 能力补强专项台账（Capability Backlog）

建立时间：2026-09-22 · 状态：**待排期**（本轮先修缺陷，专项后期做）

**这份文件回答一个问题：AI 现在还能多做什么。** 与 [issues.md](issues.md)（缺陷台账）分开维护：
- `issues.md` = **现有能力做错了**（假成功、静默失败、数据破坏）→ 修
- 本文件 = **宿主能做的、我们还没让 AI 用上**（缺口）→ 补

**依据来源**：[08-ms-vs-wps.md](p5/mcp-sweep/08-ms-vs-wps.md)（MS vs WPS 能力对照，552 行）、[07-tool-gap.md](p5/mcp-sweep/07-tool-gap.md)（工具面缺口，541 行）、[06-wps-api-map.md](p5/mcp-sweep/06-wps-api-map.md)（WPS 对象模型成员清单）。

## 依据等级口径（务必区分，不要当成已实测）

| 等级 | 含义 |
|---|---|
| **源码可证** | 我们自己的代码里能直接读出（分支存在/不存在） |
| **文档可证** | 官方 API 文档写了，但**本机未实测** |
| **推测** | 从 VBA/COM 经验推断，**未验证** |
| **已实测** | 在本机真实宿主上跑过并有读数 |

> ⚠️ 大部分"宿主支持"目前是**文档可证**而非已实测——补的时候第一步就是**实测确认**，不要直接照文档开写。

## 每个能力补齐时的"完成定义"（统一口径）

补一条能力必须同时交付，缺一不算完成：

1. **宿主实现**：`wps-addon/src/**` 或 `office-addon/src/**` 里的真实实现；
2. **工具定义**：`src/bridge/tools/definitions/**` 的 schema 与说明（写明宿主限制与参数语义）；
3. **读回能力**：有写就必须有读，否则 AI 无法自检；
4. **契约快照**：跑 `npx tsx scripts/snapshot-tools.ts` 记录差异，说明新增/变更了哪些工具；
5. **skill 说明**：`skills/office-agent-bridge/**` 里写清怎么用、有什么坑；
6. **真机验证**：在真实 WPS / Microsoft Excel 上跑出**读数**（不是"构建通过"），并把证据留档到 `docs/acceptance/`；
7. **回归**：`typecheck 0`、`npm test` 全过、`check:claims` / `check:agents` 0。

## 维护约定

- 每条补完后把"状态"改成 `已完成（日期 + 证据路径）`，**不删条目**；
- 实测发现宿主其实不支持的，状态改 `不补（宿主不支持 + 证据）`；
- 新增能力缺口一律先登记到本文件，再排期。
