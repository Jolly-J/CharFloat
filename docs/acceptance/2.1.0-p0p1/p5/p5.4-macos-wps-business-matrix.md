## 3. ⚠️ 本轮发现的真实缺陷：`excel_patch_cells` 混用 values + formulas 会静默清空数据

**触发条件**：同时提供 `values` 与 `formulas` 两个矩阵，且 `formulas` 里用空字符串 `''` 表示"这个单元格只写值、不写公式"。

**根因**（`wps-addon/src/excel.js:360-361`）：

```js
if (values !== undefined && values !== null) range.Value2 = values;
if (formulas !== undefined && formulas !== null) range.Formula = formulas;   // '' 被当作公式写入 → 清空单元格
```

赋 `''` 给 `range.Formula` 等于清空该单元格，于是**第二步把第一步刚写入的值覆盖掉了**。

**复现（可重复）**：

| 步骤 | 操作 | 观察 |
|---|---|---|
| 1 | `excel_patch_cells` 写入 `A40:D40 = ["原始A","原始B",100,"原始D"]` | 读回正确 |
| 2 | 对同一区域 `excel_patch_cells`，`values=[["新A","新B",200,"新D"]]` + `formulas=[["","","",""]]` | 返回 `success:true`、**"已成功修改 4 个单元格"** |
| 3 | 读回 `A40:D40` | **`[null,null,null,null]`** —— 既不是新值，也不是旧值 |
| 4 | `wps_rollback`（用第 2 步返回的 `auditId`） | ✔ 恢复为 `["原始A","原始B",100,"原始D"]` |

返回的 `diff` 里能看出 `newValue: null, newFormula: ""`，但**面向调用方的文案是"已成功修改 N 个单元格"**。

**严重度**：高——调用方（AI 或人）看到的是"成功"，实际效果是**目标区域被清空**。审计快照 + `wps_rollback` 可恢复，所以不是不可逆损坏，但需要调用方事后发现并手动回滚。

**规避方式（当前版本）**：把公式直接放进 `values`（已实测可行：`values=[["=1+1","=2*3"]]` → 读回公式 `=1+1`、值 `2`），**不要同时传 `formulas`**。

**处置**：属于产品行为决策，已登记为 **DP7**（见 [refactoring-plan.md](../../../refactoring-plan.md) 决策点表），未擅自修改。
