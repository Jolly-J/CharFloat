## 卡点与错误原文

1. **目标歧义（最严重，且是"静默选错"而非报错）**
   - 15:55 起：不传 `presentationName` → 命中残留锁，报错
     `Bridge HTTP 422: {"success":false,"error":"未在 WPS 中找到目标演示文稿 [Q3信息化总结.pptx]。当前已打开: 测试演示文稿.pptx, ppt3-blank.pptx"}`
     （`wps_word_read_document` / `wps_get_workspace_summary` 同样命中 `文字文稿1` / `经营&信息化 绩效完成情况.xlsx`）
   - 16:00：同样的调用**不再报错**，而是静默指向**别的代理正在用的** `bgtest.pptx`（当时 `app.Presentations.Count=4`，
     它恰好在前台）。也就是说"省略目标名"的语义是浮动的：有时报错、有时默默写别人。
   - 工具 schema 只写"不传则默认当前活动文稿"；宿主 `wps-addon/src/shared.js` 的真实顺序是
     **加载项进程级 `lockedTargets` → 唯一打开则锁定它 → ActivePresentation**，与网关 `TargetLockStore`
     （按 `sessionId:host` 分桶）语义不一致。任务开始时的环境说明只列了 3 个文件，真实是 PPT 2→4 个、
     Word 2 个，说明"已打开清单"也是动态的。
   - 缓解：全程显式 `workbookName`/`documentName`/`presentationName`；可用 `wps_lock_target_document`
     （实测：锁定后不传名也能稳定命中 `e2e-钙钛矿产业现状与展望.pptx`），但它是**加载项全局锁**，
     多代理并发时会互相覆盖，不宜滥用。

2. **原生图表数据静默丢失**（原文见步骤 3"静默失败 1"）：图表里是宿主默认 `[4.3,2.5,3.5,4.5]` /
   `类别1..4`，传入的 4/108/300 没写进去；`ser.Values=` 赋值不抛异常也不生效；`ChartData.Workbook` 为 null。

3. **`wps_ppt_capture_slide_preview` 不可用**：`Bridge HTTP 422: {"success":false,"error":"PPT 未生成预览"}`（4/4 次失败），
   而同一 API 用脚本直接导出成功——错误原因在链路中被替换成兜底文案。

4. **同一次调用两种结果**：同一份 `generate_deck` JSON，15:55 生成的是未缩放版面（矩形 720×405），
   15:58 生成的是正确缩放版面（960×540），且后者响应里多出 `layoutWarnings` 字段。
   已部署加载项（`Office Agent Bridge (演示)_2.1.0/addon-core.js`，11:51，196693 B，`c30e548a…`）
   与仓库构建物（`wps-addon/addon-core.js`，15:53，203647 B，`42e884b9…`）不一致。**根因未确证**。

5. 页码越界 / 幻灯片不存在时，报的是宿主内部 JS 错误（`Cannot read properties of null (reading 'Delete'/'Shapes')`），
   缺少中文上下文，用户无法判断是自己传错了页码。

## 对 MCP / skill 说明的反馈

1. **"多文档同时打开时该操作哪一个"没有讲清楚，这是本轮最大的说明缺口。**
   - 工具 schema 统一写"不传则默认当前活动文档"，但宿主实际优先用**进程级残留锁**；
     两者不一致，且"活动文档"在并发场景下等于"别人正在操作的那一份"。
   - skill（`SKILL.md`）只说"读取工作区摘要定位精确名称，在后续调用显式携带目标"，
     没有说明：① 不显式传名的真实回退顺序；② 残留锁会让"省略参数"命中历史文件；
     ③ 并发会话共享同一加载项时锁会互相覆盖；④ `lockedTargets` 与 `TargetLockStore` 不是一回事。
   - 建议补一条避坑："多文档/多代理环境下必须显式传目标名；`wps_lock_target_document` 是加载项全局锁，
     并发时不要依赖它做隔离；`bridge_get_capabilities` 的 '当前已打开' 列表可能不全，需用原生脚本枚举核对"。
2. **PPT 能力有个明显空洞**：没有"新建演示文稿"、也没有"保存演示文稿"工具（Word/Excel 都有保存工具）。
   skill 与 `capabilities.md` 都没提示这个缺口，只能自己发现并改用 `wps_execute_script`。
3. **图表路径的文档与实现不符**：skill 把原生图表当作推荐做法（`wps_ppt_insert_native_chart` /
   `generate_deck` 的 chart 版式），但没有"创建后必须读回图表数值"的强提示。
   本轮恰好是读回才发现数据是空的。建议把"图表必须读回 `SeriesCollection().Item(1).Values`
   核对并检查 `Formula` 是否仍指向 `Sheet1!$B$1`"写进 skill。
4. **追加型工具的幂等性没有说明**：`generate_deck` / `write_content` / `manage_table insert` 都是追加语义，
   失败后重跑会重复。skill 的"批次与恢复"一节只说"不要盲目重放整批"，可以补一句"追加型工具重跑前需先清理已写入部分"。
5. `wps_ppt_read_presentation` 返回的 `pageWidth/pageHeight` 为 `null`，而 `wps_ppt_get_slide_shapes`
