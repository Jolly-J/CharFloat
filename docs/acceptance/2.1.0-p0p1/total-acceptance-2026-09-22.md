## 三、几条分量最重的修复

### 3.1 ISS-59 构建指纹闭环（本轮最有价值的一条）

**问题**：磁盘上是新构建、WPS 进程里跑的是旧构建（部署后没重载），此前**没有任何指纹能识别**，只能靠反复试错。本项目为此踩坑两次。

**方案**：构建时对源码拼接体取 sha256 → 同时写入产物头部注释（桥接读磁盘用）与 IIFE 变量（加载项运行时报）→ 加载项在 register 报文上报 → 桥接比对给出 `runningMatchesResource` / `staleSuspect`。

**真机验证**：
```
word / excel / ppt  →  运行中 = 仓库构建 ✔
部署后未重载         →  staleSuspect: true + "新构建已生成但未重载，请重新加载"
旧加载项不上报        →  staleSuspect: null + 说明（区分"判不了"与"不一致"）
```

**并且当场兑现了价值**：本轮我两次"改了没部署/没生效"，都是它一眼看出来的。

### 3.2 ISS-96 删除伪渲染（证据可信度）

Office.js 侧 `capture_sheet_preview` 在无图表时**用 Canvas 按硬编码参数合成一张"高保真渲染图"**。AI 的视觉自查会据此得出与真实文件不符的结论——**比报错更危险**。

修复后：唯一真实路径 `chart.getImage()`；区域截图明确报错并给三条替代路径。**修复前已复现假图（44.8KB + `success:true`）**。

### 3.3 ISS-93 跨宿主字段错位（真机 10/10）

`normalizer` 只适配 14 个方法，12 个 `excel_*` 在 `host=microsoft` 时参数错位。最危险的两条：
- `set_data_validation` → **先清空既有校验再什么都不设**
- `find_and_replace` → `text=""` 时"每个非空单元格都命中"且 `replaceAll("")`，**可能破坏内容**

修复后真机验证：数据有效性真写入、插列按 `targetType`、`protect` 从静默成功改为明确报错。

### 3.4 ISS-46 回滚身份判据（真实数据破坏）

原来回滚只比"区域内容是否相等"。别人删表重建并写回**完全相同**的内容时，旧 `auditId` 会被放行、把这批新数据清空。

现改为**四道判据**：① 同区域无更晚的未回滚记录 ② 记录之后无未审计的身份类操作 ③ 目标工作表仍存在 ④ 最后才比内容。任一不满足即拒绝，并给出替代路径。

| ISS-111 | **Word 预览恒不落盘**（输出到 WPS 沙箱写不了的位置） | 需要真实宿主才能发现 |
| ISS-112 | **宿主方法被摘出后丢 this** → `Address called on null or undefined` 被吞掉，表现为地址为空 | 同上 |
| ISS-66 | 同上（ISS-112 的表象） | 同上 |

### ISS-111 的排查链（示范）

不直接改代码，而是**逐条实测宿主可写性**：

```
~/.wps-bridge/previews/   ❌ WPS 沙箱写不进去
os.tmpdir()               ❌
~/Downloads/.子目录/      ❌（根目录可以，子目录不行）
WPS 自己的容器 tmp        ✅
```

根因是预览输出到了 WPS 写不了的地方。修复后 Word 预览真的写出 615,621 字节 PDF。

### 方法学教训（已写入台账）

1. **验"写操作"必须在一个脚本里成对完成**（hide→读→unhide），跨脚本会被前一步的状态污染。
2. **验"防护逻辑"必须先构造出触发条件**（叠图 ≥2），否则得到的是假通过。
3. **判断运行版本要用行为差异**，不能用作用域探测——`wps_execute_script` 用 `new Function` 执行，看不到加载项 IIFE 内的 `var`。
4. **子代理结论必须回代码或真机复核**——本轮累计推翻 4 条误报（ISS-41、ISS-47、`excel_create_sheet`、`wps_reload_addon` 的效果）。
