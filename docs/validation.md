# 2.0 验证矩阵

## 已在本次开发环境运行

- TypeScript 无输出检查、renderer/main/CLI 构建。
- 配置合并：保留其他 MCP 条目，损坏 JSON 拒绝写入。
- WPS 索引：保留其他插件，损坏 XML 拒绝部署，状态检查不创建目录。
- 鉴权与来源校验：匿名只读 health，办公状态和工具需要本机凭据。
- HTTP MCP 初始化、工具列表、能力资源、模拟 WPS RPC。
- 双 stdio 客户端复用已运行服务，退出一个不影响另一个。
- 单元格回滚拒绝覆盖后续修改，匹配快照时恢复原值。
- 新客户端通过独立临时运行目录、端口启动；退出管理器后后台 PID 保持不变。

这些测试使用模拟宿主，不能证明 Office/WPS 对象模型在真实 Windows 版本中的行为。

## Windows Office

先运行 `powershell -NoProfile -File tests/windows-office.ps1` 检查脚本语法。

需要实机操作验收时显式添加 `-RunOffice`。测试创建自己的 Excel 实例、中文名称临时工作簿，覆盖值/公式、样式、条件格式、图表、透视表、排序、验证、截图和直接回滚。测试结束仅关闭它创建的实例，保留临时文件供检查。

还需人工覆盖：Office 2019/2021/365 版本差异、中文用户名及空格安装路径、多实例、文档受保护/只读、失去 COM 注册、后台重启、Office 权限高于 Bridge、系统脚本执行策略。

## Windows / macOS WPS

1. 新建独立测试工作簿，保存为明确测试名称。不要在正式文件中运行测试脚本。
2. 部署 2.0 加载项，确认 publish/jsplugins 索引中原有插件仍在。
3. 启动 Bridge，打开表格；检查宿主版本、工作簿与活动表。
4. 用统一 excel_* 工具显式指定 host、workbookName、sheetName，测试读取、写入、公式、格式和图表。
5. 写入后读回并截图；确认预览结果与当前文件一致。
6. 先做人工后续编辑，确认旧审计回滚被拒绝；再用未变动的测试区域验证回滚。
7. 两个 AI 同时连接、关闭其中一个、关闭管理窗口、恢复窗口，确认剩余客户端可继续读取。
8. 主动停止后台，确认 Agent 获得清晰错误；重新启动后检查加载项重连。
9. Word/PPT 使用各自独立测试文档，验证基础读取、编辑、保存和预览；失败应返回错误，不得用占位对象冒充成功。

## 桌面界面

默认 880×620，最小 760×560；检查概览、接入、记录、设置、主题、键盘焦点、对话框、禁用与错误状态、减少动态效果。安装与外部配置操作仅在明确选择后发生。
