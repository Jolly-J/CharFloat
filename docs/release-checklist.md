# 版本验收与发布清单模板

将本清单填入 `docs/acceptance/<候选标识>/README.md`，已有报告则合并相应项目；不要覆盖历史证据。规则见 [版本与发布制度](release-policy.md)。未做标“未验证”，不适用项写理由；只有负责人明确接受的缺口可以随限制发布。

## 构建与验收

- [ ] 目标版本和平台已确认，交付范围已归入 CHANGELOG。
- [ ] `npm run check:version`、`check:agents`、`check:brand`、`check:claims`、`typecheck` 通过。
- [ ] `npm run build` 和 `npm test` 通过，模拟结果单独标注。
- [ ] 发布副本构建完成，双平台串行、输出隔离、`--publish never`，退出码均为零。
- [ ] 对最终 `.app` 和 ZIP 分别完成 `check:release`，记录实际文件哈希及架构、版本、签名、unpacked 核验。
- [ ] 对包内真实 CLI 完成隔离运行与 MCP 契约验证，记录实际执行路线。
- [ ] 受影响的安装/更新/桌面流程验证，或注明不适用理由。
- [ ] 受影响平台使用实际发布加载项完成真实宿主读回；持久化涉及保存关闭重开，或注明缺口及负责人接受记录。
- [ ] 旧正式版本包和指纹保留；本次产物符合目录口径。

## 正式发布（只在明确授权后执行）

- [ ] 发布说明包含变化、兼容性、签名口径、已知限制与未验收平台。
- [ ] 发布源码归入固定提交；构建输入与提交一致，`v<版本>` 标签指向该提交。
- [ ] 发布授权记录：谁、何时、批准范围、接受的验收缺口。
- [ ] 上传已验收的同一份包；mac ZIP 来源 `.app` 一致并记录 ZIP 哈希。
- [ ] 远端附件名、大小、`digest` 与本地 SHA-256 对账一致。
- [ ] 记录发布地址、时间、标签、源码 SHA；状态更新为正式发布并冻结。

正式发布记录保存在本证据目录，可在 `release/<版本>/verification/publication.json` 留副本；不得只存放在被 Git 忽略的 `release/` 中。
